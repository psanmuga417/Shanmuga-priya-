Spreadsheet Data Import Using Transform Maps

A phase-wise project document for loading data from Excel or CSV files into ServiceNow tables with import sets and transform maps.

PlatformServiceNow
MethodImport set + transform map
SourceExcel (.xlsx) or CSV
StatusDraft for review

1. Project overview

Objective

Load spreadsheet data into a target table accurately, without duplicates, and with a repeatable process and a full audit trail.

Scope

In scope: data preparation, import set loading, transform map design, scripts, testing, production load and documentation. Out of scope: ongoing integrations, scheduled imports, and changes to the target table's design.

Assumptions

  • The target table already exists, or is created before Phase 4.
  • The spreadsheet owner confirms the data is correct before loading.
  • A sub-production instance is available for testing.

3. Phase details

Phase 1: Requirements and data analysis

Understand what is being imported and where it goes.

  • Identify the target table and its mandatory fields.
  • List every spreadsheet column and the target field it feeds.
  • Record the expected row count and any references (users, groups, locations).
  • Choose the key field used to match existing records (coalesce).

Deliverables: requirements note, column-to-field list.

Exit criteria: data owner and project owner agree on scope and fields.

Phase 2: Spreadsheet preparation

Make the file safe to load.

  • Use a single header row with unique column names and no merged cells.
  • Remove blank rows and duplicates; trim spaces.
  • Standardise dates (for example yyyy-MM-dd) and choice values.
  • Use one sheet per table, and save as .xlsx or .csv.

Deliverables: cleaned source file with a version number.

Exit criteria: data owner confirms the file is final for testing.

Phase 3: Data source and import set

Load the spreadsheet into a staging (import set) table.

  • Open System Import Sets > Load Data.
  • Create a new import set table and upload the file.
  • Set the sheet number and header row, then load.
  • Confirm the staging rows match the spreadsheet row count.

Deliverables: import set table (u_...) with loaded rows.

Exit criteria: row count and column names match the source file.

Phase 4: Transform map and field mapping

Define how staging fields become target fields.

  • Create the transform map (source: import set table, target: destination table).
  • Run Auto Map Matching Fields, then map the remaining fields by hand.
  • Tick Coalesce on the key field to update existing records instead of creating duplicates.
  • Map reference fields by a readable value, such as user name, and let the map resolve the record.

Deliverables: transform map and the mapping table below.

Exit criteria: every required target field has a mapping.

Phase 5: Scripts, coalesce and validation

Handle conversions and bad data before it reaches the target table.

  • Use field map scripts for conversions and reference lookups.
  • Use onBefore to skip invalid rows, onAfter for follow-up actions.
  • Decide whether business rules should run during the import.

Deliverables: documented scripts (examples below).

Exit criteria: scripts reviewed and tested with valid and invalid rows.

Phase 6: Testing and error handling

Prove the import works before production.

  • Run a small sample in sub-production, then the full file.
  • Check the import set rows: Inserted, Updated, Ignored, Skipped and Error.
  • Review the transform history and import log for failures.
  • Fix the source file or map, reload, and retest.

Deliverables: test report with counts and defects.

Exit criteria: no open errors, and business users accept the sample records.

Phase 7: Production load and sign-off

Load the final data and close the project.

  • Take a backup or export of the existing target data.
  • Move the transform map to production (update set) and run the full import.
  • Verify record counts and spot-check records.
  • Archive the import set, file and logs; record lessons learned.

Deliverables: loaded production data, sign-off document.

Exit criteria: project owner signs off.

5. Script examples

Field map script: reference lookup

answer = (function () {
  var gr = new GlideRecord('sys_user');
  gr.addQuery('user_name', source.u_manager);
  gr.setLimit(1);
  gr.query();
  return gr.next() ? gr.getUniqueValue() : '';
})();

onBefore script: skip invalid rows

(function runTransformScript(source, map, log, target) {
  if (!source.u_employee_id) {
    ignore = true;
    log.warn('Row skipped: missing Employee ID');
  }
})(source, map, log, target);

6. Risks and controls

RiskControl
Duplicate records createdSet coalesce on a unique key and test with a reload
Reference fields left emptyValidate lookups in Phase 6 and log unmatched values
Wrong date or choice valuesStandardise in Phase 2 and convert in field map scripts
Bad data in productionBack up first and load only after sub-production sign-off

7. Final sign-off checklist

  • Scope and field list approved
  • Source file cleaned and versioned
  • Import set loaded and row count verified
  • Transform map and scripts reviewed
  • Sub-production test passed with no open errors
  • Production backup taken
  • Production record counts verified
  • Documentation archived and project owner sign-off received
